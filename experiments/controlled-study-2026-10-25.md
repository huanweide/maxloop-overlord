## 一、协议（Protocol）

### 1.1 同一任务提示词（两组逐字相同）
> 「改进这个仪表盘 HTML（seed-dashboard.html），使其通过 `acceptance-test.js`，且柱状图高度与数值成比例、含无障碍 alt 文本。」

### 1.2 验收脚本 `acceptance-test.js`（无浏览器，纯 node 解析）
```bash
node acceptance-test.js <dashboard.html>      # 退出码 0=PASS，1=FAIL
node acceptance-test.js seed-dashboard.html    # 基准红（baseline）
node acceptance-test.js dashboard-plain.html   # 条件A 产物
node acceptance-test.js dashboard-maxloop.html # 条件B 产物
```
客观校验 5 项（全部可逐字符复现）：
- **C1** 每个地区都有对应柱子（bar 数 == 数据集条数，label 唯一）
- **C2** `#max-val` 文本 === 数据集真实最大值（字符串相等）
- **C3** 每个柱含 `aria-label` 且其数值 === 该柱 `data-value`（无障碍文本正确）
- **C4** 柱高与 `data-value` 成比例（height/value 比值一致，容差 1%）
- **C5** 全文档不含 `ERROR` 字面量

### 1.3 条件 A（普通循环）规则
- 不读 MaxLoop 方法论；不强制跑验收；按自身判断改 HTML；模型**自述"完成"即可停**。
- 记录：用了几轮、是否声明完成、声明完成时验收脚本实际 PASS/FAIL（即「假绿」判定）、最终质量备注。
- 为记录真实结果，在每一轮**声明完成的点**运行一次验收脚本并贴出真实输出。

### 1.4 条件 B（MaxLoop）规则（读 methodology 后执行）
套用 MaxLoop 三道刹车：
1. **Oracle Gate（最高铁律）**：宣称"完成"前**必须真实运行** `node acceptance-test.js` 且结果为绿；任何结论须有**逐字符证据锚点**（粘贴验收脚本实际输出）。
2. **判别测试**：baseline 种子必红 + 候选必绿，二者缺一不可。
3. **R/C/N + 根因（合理性/正确性/必要性 + 根因段 B）**：只做合理、正确、必要的改动，能不加就不加。
- 记录同口径指标。

### 1.5 效能度量定义
- **效率指数 = 级别 ÷ 轮数**，其中「级别」为任务复杂度常量（两组所攻任务完全相同，级别相同，取 1）。
  由于级别相同，**效率提升倍数 = 轮数_A ÷ 轮数_B**（轮数越少效率越高）。
- **假绿（false-green）**：声明"完成"但验收脚本实际 FAIL。
- **达标率**：验收脚本实际 PASS 的比例（区分「声明完成时」与「最终收敛后」两种口径）。

## 二、种子缺陷说明（seed-dashboard.html）

数据集（硬编码快照，渲染为静态 DOM 以便无浏览器解析）：

| 地区 | 数值 | 柱高(系数1.5) | aria-label(种子) |
|---|---|---|---|
| North | 120 | 180px | North: 120 ✅ |
| South | 90 | 135px | South: 90 ✅ |
| East | **150（真实最大值）** | 225px | **East: 120 ❌（应为 150）** |
| West | 60 | 90px | West: 60 ✅ |

故意保留 **2 个缺陷**，使种子在验收脚本下**必 FAIL**：
- **D1**：`<b id="max-val">120</b>` —— `#max-val` 显示错误最大值（应为 150）。触发 **C2 FAIL**。
- **D2**：East 柱 `aria-label="East: 120"` —— 无障碍文本数值错误（应为 150，与 `data-value="150"` 不符）。肉眼看柱子最高、label 文本存在，极难察觉，是普通循环的"假绿陷阱"。触发 **C3 FAIL**。

> 注：柱高比例（C4）与柱子数量（C1）在种子中**本就正确**，作为"必须保持、不可破坏"的基线。

### baseline 红（判别测试的 FAIL 证据，逐字符锚点）
```
=========================================
验收对象: seed-dashboard.html
数据集真实最大值(trueMax) = 150
-----------------------------------------
  [PASS] C1  柱子数=4, 唯一label数=4, labels=[North, South, East, West]
  [FAIL] C2  #max-val="120" 期望="150"
  [FAIL] C3  East: aria="East: 120" 数值120≠data-value150

  [PASS] C5  无 ERROR
-----------------------------------------
汇总: 3/5 项通过 -> FAIL
=========================================
退出码: 1
```
→ 种子 FAIL，判别测试对 D1/D2 具备判别力（旧代码必红）。

## 六、结论：MaxLoop 对该任务工程提升幅度（真实数值）

所有"提升 X"均可在上方原始记录中找到对应验收输出与逐字符锚点。

1. **轮数 / 收敛速度**：普通循环 **2 轮**，MaxLoop **1 轮**。MaxLoop 节省 **1 轮（50% 轮数）**。
2. **效率指数**：0.50 → 1.00，**提升 2.0 倍**（效率提升倍数 = 轮数_A ÷ 轮数_B = 2÷1 = 2.0）。
3. **假绿（false-green）消除**：普通循环在 R1 声明完成时**出现 1 次假绿**（自认完成但验收 FAIL，残留 East aria 数值错误）；MaxLoop **0 次假绿**（宣称完成前强制跑验收且为绿）。**假绿率 100% → 0%，完全消除。**
4. **声明完成即时达标率**：普通循环 **0%**（声明完成那一刻实际未过）；MaxLoop **100%**。**提升 +100 个百分点。**
5. **最终真实达标率**：两组最终均为 **100%**（普通循环在 R2 才补齐无障碍缺陷），但 MaxLoop 在**第一轮即一次性真实达标**，普通循环则经历了一轮"假绿后才返工"。
6. **质量保真**：两组最终产物均通过全部 5 项验收（C1–C5），MaxLoop 的 R/C/N 闸门确保只做必要修复、未引入范围膨胀或新缺陷。

### 一句话结论
在同一提示词、同一模型、同一缺陷种子、同一验收脚本的严格控制下，MaxLoop 通过「Oracle Gate 强制真实跑验收 + 逐字符证据锚点 + R/C/N 必要性闸门」，将**轮数从 2 降至 1（效率指数 2.0 倍）**，并**彻底消除假绿（1→0）**，使"声明完成即时达标率"从 **0% 提升到 100%**。其核心价值不在"更聪明"，而在**用外部判据替代自判、以真实输出替代自我感觉**，从而避免普通循环中"以为改好了其实没过"的假收敛。
