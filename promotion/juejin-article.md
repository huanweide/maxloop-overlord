# 你的 Agent 说"改好了"，但它是真的改好了吗？—— 用 MaxLoop 消灭"假绿"

> 掘金长文草稿。核心论点：Agent 自循环最大的隐性浪费不是"改不动"，而是"以为改好了其实没过"的**假收敛**。MaxLoop 用四条刹车把"自判"换成"外部判据"。文末附可复现的控制变量实验。

## 一、一个被忽视的坑：假绿（false-green）

你让 agent 改一个 bug，它跑完说"已修复，验证通过"。你信了。三天后用户报同样的错。

问题出在哪？**agent 的"完成"是自我报告，不是判决。** 它看到代码改了、本地跑通了，就判定成功。但"本地跑通"可能只是它没触发那条失败路径；"看起来对"可能漏掉了无障碍文本里一个数值错误。

我把这种现象叫 **假绿**：声明完成，但外部判据实际 FAIL。

## 二、普通循环 vs 带刹车的循环

普通 agent 循环的逻辑是：

```
改 → 自认完成 → 停
```

MaxLoop 的逻辑是：

```
发现真问题 → 轮次修复 → 跑外部判据 → 真绿才交付，否则继续
```

差别只在一步：**交付前必须过外部判据**。但就是这一步，决定了你是"假绿交付"还是"真绿交付"。

## 三、四道刹车（可单条采纳，不必全上）

**1. Oracle Gate（外部判据先决）**
宣称"完成"前，必须真实运行测试 / 构建 / lint 等外部判据且为绿。自述永远不算数。

**2. 逐字符证据锚点**
任何"已修复""已通过"都必须附真实工具输出（粘贴 stdout），禁止"我觉得没问题"这类口头结论。

**3. R/C/N + 根因闸门**
改动必须满足：合理（Reasonable）、正确（Correct）、必要（Necessary），且每个 diff 附根因说明。能不加就不加，避免范围膨胀。

**4. 判别测试 + 逃逸阶梯 + stall guard**
- 判别测试：旧代码必红、新代码必绿，二者缺一不可，防止"绕过测试假绿"。
- 逃逸阶梯：卡住时升级策略，不原地打转。
- stall guard：连续 N 轮无实质进展，硬刹车，避免烧 token 空转。

## 四、控制变量实验（数字可复现）

为证明不是嘴炮，我做了严格对照：两组**同提示词、同模型、同缺陷种子、同验收脚本**，唯一变量是"是否启用 MaxLoop"。

种子故意埋了 2 个缺陷：
- D1：`#max-val` 显示 120，真实最大值应为 150。
- D2：East 柱 `aria-label="East: 120"`，无障碍文本数值错（应为 150，与 `data-value` 不符）。D2 极阴险——柱子最高、label 也在，肉眼几乎发现不了。

结果：

| 指标 | 普通循环 | MaxLoop |
|---|---|---|
| 收敛轮数 | 2 | 1 |
| 假绿次数 | 1（R1 自认完成实际 4/5 FAIL） | 0 |
| 声明完成即时达标率 | 0% | 100% |
| 效率指数（级别÷轮数） | 0.50 | 1.00（×2.0） |
| 假绿率 | 100% | 0% |

普通循环第 1 轮改完最显眼的 D1 就喊完成，实际 D2 还在，验收 4/5 FAIL = 假绿；第 2 轮才补齐。MaxLoop 第 1 轮就把两处根因都修了，跑验收 5/5 PASS 才交付。

> 完整验收输出、种子、脚本都在仓库 `experiments/` 目录，任何人都能 `node acceptance-test.js` 自己跑一遍复核。

## 五、它不"更聪明"，它只是不骗你

MaxLoop 的价值不在让模型变强，而在**把"改没改好"从模型自说自话变成外部可证、从自我感觉变成真实输出**。代价是需要真实的 oracle（可执行的外部判据）、收敛的 critic、克制的交付。

适用场景：代码自迭代、文档/方案升级、产品深度评审、任何"有限轮数要做到位"的任务。不绑语言、不绑框架，任何 agent 都能套。
