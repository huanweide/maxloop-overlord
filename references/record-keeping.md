# 记录要求（MaxLoop 魔王系统 · 阶段六）

本技能要求双文档留痕：**改动记录** + **会议记录**。在系统判定「项目已无问题」之前持续维护，不得省略。

## 一、改动记录（自身所有改动）
- 形式：项目原生变更日志。示例项目用双 changelog（根 `CHANGELOG.md` + `src/lib/changelog-data.ts`，见适配层）。
- 每次升版须含：版本号、日期、4 条摘要、具体改动列表（对齐 IMP 编号）。
- 每次 commit 须将变更日志与代码同提交；推送后回写项目记忆（`.workbuddy/memory/`）。

## 二、会议记录（每次开会讨论结果）
- 落盘路径：`PROCESS/meetings/round-N/`
  - `<agent>.md`：阶段一各 Agent 深度体验报告（≥1 万字）。
  - `_integration.md`：阶段二整合 + 逐条投票结果（票数 / 认可者 / 反对理由）+ 改进清单（IMP-xxx）。
  - `_solutions.md`：阶段三逐条完整方案（覆盖全部要点，含验证方式与风险）。
- 格式：Markdown；每条含提出者、证据锚点、决策、验证结论。
- 观察池：未入清单问题归档于 `_integration.md` 末尾，标注「待下轮复核」。

## 三、总结报告（循环终止时）
输出一份总结（落 `PROCESS/release-<version>-report.md`）：
- 干了什么（一句话）、为什么这么做（第一性原理）、方法工具与效果、关键取舍、诚实边界、里程碑。
- 附最终门禁全绿证据与「改进清单归零」证明（IMP 全 closed + 复验报告无残留）。
- 采用费曼式写法：零基础可读，术语先讲大白话再配类比，结论可复现。
