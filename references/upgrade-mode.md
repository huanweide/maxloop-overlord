# 模式B · 方案升级循环（MaxLoop v4.0 细则）

> 本文件是统一引擎 **模式B（方案升级循环）** 的完整细则，由 v3.3 前的独立 skill `maxloop-upgrade` 吸收而来。模式A（产品深度迭代）请见主 SKILL 与各 `references/` 协议。两模式共用主循环、统一刹车系统（主 SKILL 第三节）与 critic 角色（第六节）。

## 一、何时进入模式B

用户说以下任一类话即进入模式B（其余触发走模式A）：
- "maxloop 升级方案" / "不断优化" / "三轮校验"
- "在 PPT / 中期汇报 / 需求文档基础上优化"
- "不要强行加东西" / "不要停止" / "监督 agent 模拟我自己"

## 二、铁律（最高优先级，违反即中止）

1. **基准 = 模板原档**：原始 PPT / 中期汇报 / 需求文档是基准。所有升级都在其上加，**不另起炉灶、不推翻原结构、不强行加东西**。
2. **只合理化升级**：功能/模块/传感器只有"合理 + 必要"才加；能不加就不加；改要讲清为什么。
3. **三轮校验门禁（R/C/N）**：每个"添加 / 修改 / 抉择"落盘前必须逐条过三关，任何一关不过 → **打回或降级**，禁止落盘：
   - **合理性 R（Rationality）**：逻辑站得住吗？和项目定位、目标场景、核心差异化一致吗？
   - **正确性 C（Correctness）**：事实/数据/技术依据对吗？有来源吗？现场演示会不会翻车？**须逐字符证据锚点**（融合主 SKILL 3.1e）。
   - **必要性 N（Necessity）**：非改不可吗？不改会怎样？有没有更轻替代？是否和差异化冲突？
4. **禁止幻觉**：所有事实标来源；查不到写"查不到"；不编数字；不把研究结论当已落地方案。
5. **不要停止**：循环推进，每轮产出可继承的升级 delta；可接 recurring automation 持续运行，直到用户喊停或无可升级项。

## 三、角色

- **主 Agent（Chair）**：执行升级、答 critic 质询、过三轮门禁、落盘、维护台账。
- **监督 Agent（critic 角色，模拟用户）**：由一个子 Agent 扮演——批判性强、工程思维、要求来源、反感强行加功能、要求"讲人话"。它**持续搜索新证据** + 对候选改动提出质询（"为什么改？依据呢？不加行不行？会不会和差异化冲突？"）。

## 四、流程

- **S0 载入**：模板原档 + 现有知识库/研究结论（如 `伴学终端_调研知识库.md`）。
- **S1 监督 Agent 输出**：① 待升级点清单（原档与研究的 gap）② 本轮新搜索发现（带来源）。
- **S2 主 Agent 候选**：对每个点给候选改动（明确"改了什么 / 为什么 / 基于哪条研究"）。
- **S3 三轮校验门禁**：逐条记录 R / C / N 结论 + 过关 / 打回 / 降级理由。
- **S4 落盘**：把过关 delta 合入方案文档，标注每处改动的 R/C/N 判定；记录未决项（待挖 / 待问老师）。
- **S5 回到 S1**：循环，直到用户喊停或无可升级项。

## 五、输出物

1. **方案升级文档**：在原档结构基础上，逐节标注升级点 + R/C/N 判定 + 来源（例：`伴学终端_升级方案.md`）。
2. **三轮校验台账**（表格）：`改动项 | 合理性R | 正确性C | 必要性N | 结论 | 依据`。

## 六、美化与用词纪律（PPT 交付物专用）

针对最终 PPT 的"美化"与"用词"，额外加一条硬纪律：**不该写进 PPT 的，绝不写**。

- **美化** = 版式 / 配色 / 可读性 / 投影清晰度；不是往页面里塞新论点、新卖点、新功能。
- **用词** = 把已有内容讲清楚、讲精炼、讲准确；不是发明新事实、新数据、新功能。
- 三轮校验同样适用于每条"美化 / 用词"改动：
  - **R**：这处润色是否让表达更准、更读得懂、更贴合定位？
  - **C**：改后的措辞 / 数字是否仍与原文及来源一致（不漂移、不夸大）？
  - **N**：不改会不会影响答辩表达（不影响就别动）？
- **红线**：禁止在 PPT 里加"金句 / 口号 / 自我拔高 / 未核实的形容词"；禁止为凑页数或显高级而写原档没有的论述；原档没有的结论，**宁可留白也不要编**。

## 七、红线

- 禁止未过三轮门禁就落盘改动。
- 禁止为"显得高级"而加传感器/功能（必要性关会拦）。
- 禁止推翻已查证结论，除非有更强新证据且重新走三轮。
- 禁止把"研究/查证结论"直接当"已落地的方案"——研究是输入，模板原档才是被升级的对象。

## 八、示例（伴学终端）

- 候选改动"砍掉 ToF" → R：雷达 UART 已含距离，逻辑自洽；C：LD2410C 数据帧确认含检测距离(cm)，来源 datasheet；N：省一路 I2C + 一颗传感器 + 成本，且雷达测距比 ToF 更不怕遮挡 → **过关**。
- 候选改动"加一个温湿度传感器" → R：和专注/陪伴定位无关；C：无所谓；N：强行加，无必要 → **打回**。

## 九、与主 SKILL 刹车系统的对接

- 模式B 的 R/C/N 即主 SKILL **3.2 合理-必要闸门**的落地细则。
- 监督 Agent ≡ 主 SKILL **第六节 critic 角色**。
- 候选改动同样受 **3.1 Oracle Gate + 逐字符证据锚点**、**3.3 判别测试**、**3.4 逃逸阶梯 + stall guard** 约束：连续 N 轮同一升级点无新进展（stall guard 触发）→ 强制讨论/换角度/移出，不无限润色。
- 每轮末填 **效率指数**（产出级别/时间/效率指数），使方案升级也可量化收敛。
