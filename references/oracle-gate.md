# Oracle Gate · 外部判据先决条款（v3.0 最高铁律）

> 一句话：**不允许模型自己判定自己修好了。** 判据必须来自模型之外。

## 一、为什么这条最高

我们在真实项目上烧了 6 轮（0.6.19→0.6.26），每一轮都是「测试全绿」：

```
358/0 → 373/0 → 397/0 → 413/0 → 421/0    # 每一轮都全绿
```

但每一轮都被独立对抗验证员挖出新 P1。**失败不是因为不努力，是因为判据本身是内部的。**

学术依据：
- **Huang et al., ICLR 2024**《LLMs Cannot Self-Correct Reasoning Yet》——没有外部 oracle 时让模型自判「修好了没」，收益蒸发。
- **CRITIC（Gou et al., ICLR 2024）**——不要求模型自评，让它调工具，**工具输出才是 critic**。

## 二、什么算数（放行清单）

声明「修好了」必须同时具备：

| # | 判据 | 具体要求 | 为什么这条存在 |
|---|---|---|---|
| a | **目标命令真实执行** | 贴完整 stdout，不是「应该能过」 | 最简单也最容易造假 |
| b | **lint / 类型检查** | 在**改动的文件**上跑过 | 全库跑会掩盖未编译的新文件 |
| c | **★ 真实入口可达性** | 从用户实际调用点发起，不是直接调底层函数 | **本项目最贵的教训**：多次出现「单测绿但入口不可达」，累计贡献 3 轮返工 |
| d | **★ 修复前失败输出**（= `discriminating-test.md` 的 **baseline FAIL 证据**） | 见 `discriminating-test.md` | 否则不知道这个测试锁住了什么 |

## 三、什么不算数（禁止清单）

| 说法 | 为什么不算 |
|---|---|
| 「diff 看着合理」 | 眼睛不是 oracle |
| 「reviewer 认可了」 | critic 不是 oracle（这正是事故成因） |
| 「我判断应该没问题」 | 自评即失效 |
| 「测试数量增加了」 | 数量 ≠ 覆盖；新测试若在原代码上也通过则锁不住任何东西 |
| 「上一轮绿了，这轮只改了一行」 | 一行也能炸生产入口 |

## 四、Chair 执行模板

阶段五复检时，Chair **必须**在会议记录里填这张表，缺任一行不许放行：

```markdown
### Oracle Gate · round-N · IMP-xxx
| 判据 | 证据（贴命令 + 输出摘要） | 通过 |
|---|---|---|
| a 目标命令 | `node test/run.js` → `通过 421 / 失败 0` | ✅ |
| b lint/类型 | `npx tsc --noEmit` → 0 error | ✅ |
| c 入口可达 | 从 `handleDialog` 发起，spy 记录 clickOption 实参 = [...] | ✅ |
| d 修复前失败 | 旧代码上同用例输出 `texts=["2","3"]`（FAIL） | ✅ |
```

**任何一行无法填写 → 打回阶段四重做，不许「先合再说」。**
