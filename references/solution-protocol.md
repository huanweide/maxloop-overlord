# 解决方案制定协议（MaxLoop 魔王系统 · 阶段三）

## 一、开会方式
针对阶段二产出的改进清单（IMP-xxx），再次开会逐条讨论。每条必须产出**完整、可直接落地**的方案，使代码执行 Agent 能快速实施而无需二次思考。

## 二、单条方案模板（必填全项）
```
IMP-ID: <编号>
问题: <一句话复述>
根因: <为什么会出现，定位到具体代码 / 逻辑>
方案: <完整修改思路，覆盖全部要点>
涉及文件: <精确路径列表>
具体改动:
  1. <文件A>: <改什么、改成什么（意图级，精确到函数 / 行）>
  2. <文件B>: <改什么、改成什么>
验证方式: <如何证明修好了：单元测试 / 真机脚本 / 手动步骤>
风险与回滚: <可能影响的点、如何回退>
预计需汇报: <否 / 是（若预计执行中会触发阶段四「必须汇报」情形，提前标注>
```

## 三、质量要求
- 方案须**覆盖全部要点**，不留「待定」「视情况」「后续再议」。
- 涉及文件须精确到路径；改动须精确到「改前意图 → 改后意图」。
- 验证方式须可执行、可判定通过 / 失败（给出命令或断言）。
- 若现行方案完全无法解决（阶段四 a 类），在方案阶段即应标记，触发重新开会而非硬上。

## 四、输出
- 写入 `PROCESS/meetings/round-N/_solutions.md`：每条 IMP 对应一个完整方案块。
- Chair 复核方案完整性（无空项、验证可执行）后，方可进入阶段四派发代码执行。
