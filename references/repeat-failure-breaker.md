# Repeat Failure Breaker · 重复失败打破器（2-3-4 阶梯）

> 一句话：**同一问题失败两次就必须换打法，第三次换问题本身，第四次认输。不允许第四次还用第一招。**

## 一、为什么需要

默认失效模式：**同一缺陷在第 R 次修复时，仍然重复第 R-1 次的同一套动作**，只是参数微调。
这不是「再试一次」，这是**对着墙用同样姿势撞**。每一轮消耗同样的预算，产出同样的失败。

阶梯规则的本质：**强制在失败计数上挂钩行为变更**，而不是靠"意志力记得换方法"。

## 二、阶梯规则

| 轮次 | 代号 | 强制动作 | 禁止动作 |
|---|---|---|---|
| **R1** | 首次尝试 | 按 `root-cause-protocol` 定位 → 修 → 用 `discriminating-test` 验证 | — |
| **R2** | **换人** | 换一个 worker 从头独立审查，**不告知上一次的结论** | 禁止同一 worker 沿用上一轮思路继续改 |
| **R3** | **换问题（pivot）** | 重新定义问题：是不是在解一个错误的问题？pivot 到相邻可解子问题或降级路径 | 禁止再碰同一处代码做第三次同构修改 |
| **R4** | **认输移出** | 承认当前不可解，**移出本轮清单**，写入 ERROR 台账，标注阻塞原因与前置条件 | 禁止无限重推；禁止标记为"待解决"继续占坑 |

### R2「换人」的正确姿势

```
✗ 错：把上一轮的分析报告喂给新 worker，让它"看看哪里还能改"
      → 新 worker 会被锚定，产出高度同构的第三次失败

✓ 对：给新 worker 的现象描述 + 代码路径 + 复现命令，
      明确要求"独立完成 root-cause-protocol，不要参考既有结论"
```

### R3「换问题」的三种 pivot

1. **拆子问题**：整体解不了 → 拆出能解的最小切片先交付
2. **绕外层**：A 路径堵死 → 是否存在等价的 B 路径（如：抓包改 UI、换 API 换 DOM）
3. **降标准**：做不到全自动 → 先做半自动（人工确认一步）；做不到实时 → 先做离线批处理

### R4「认输」不是失败，是止损

R4 必须留**可复盘的遗产**，否则等于白烧：

```markdown
### R4 移出记录 · IMP-xxx
失败轮次：R1(结论) → R2(结论) → R3(结论)
已排除的路径：①… ②… ③…（写清楚，后人不必重踩）
当前阻塞根因：技术上不可行 / 缺外部依赖 / 缺信息
解锁前置条件：满足 X 之后可重开（写具体）
```

## 三、失败计数怎么算

- **同一 root cause** 的再次出现 = 计一轮，即使报错文案变了
- **换了 Root Cause 编号**（新的 R-nnn）= 重新从 R1 开始，不继承计数
- 若修复引入新缺陷导致原问题回填 → **算同一 root cause**，计一轮并叠加

## 四、反模式清单

| 反模式 | 为什么是坑 |
|---|---|
| 「这次我改得更彻底了」 | 同一招的加强版仍是同一招，属 R1 重复 |
| 「换个 prompt 再问一次」 | 换措辞不是换打法 |
| 「让它多跑几轮循环」 | infinite loop 不是破解手段，是预算黑洞 |
| 「四个 worker 同时想」 | 并发同源 = 高 correlated 失败，不是真正的 R2 |
| 「先放着，回来再看」 | 不算 R4，属于逃避记账，回来还得从 R1 走 |

## 五、输出格式

每轮结束必须留痕：

```markdown
### Repeat Trace · IMP-xxx · R{n}
本轮打法：<一句话，必须与上一轮不同，写清楚差别在哪>
本轮结果：通过 / 失败（附 discriminating-test 输出）
若为失败：已排除假设 = [...]；下一轮强制动作 = R{n+1} 的 <换人 / pivot / 认输>
```

## 六、与相邻文件的分工

```
repeat-failure-breaker → 决定「什么时候必须换打法」（横向的时间轴）
root-cause-protocol    → 决定「这一轮往哪里打」（纵向的深度轴）
degrade-protocol       → R3 pivot 失败后、R4 之前的缓冲层（降级交付）
```
