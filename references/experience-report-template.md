# 深度体验报告模板（MaxLoop 魔王系统 · 阶段一）

> 适用对象：每位「开会子 Agent」在每轮深度体验阶段独立撰写。
> 硬性要求：不少于 1 万字；以「用户体验视角 + 总体视角」双栏并行。
> 诚实边界：所有内容须基于真实代码阅读、测试运行或真实操作证据，禁止编造。

## 报告头（必填）
- Agent 代号 / 透镜职责：
- 所属轮次（round-N）：
- 体验对象（产品 + 版本 + 入口 URL / 命令）：
- 日期：

## 第一部分：用户体验视角（约 5000–6000 字）
以「真实用户」身份走通主流程，记录自身操作体验：
1. **自身操作体验**：点了什么、等了多久、是否符合预期、有无卡顿 / 报错 / 空响应 / 静默失败。
2. **功能与看法评价**：每个功能是否真的有用、是否解决痛点、有无画蛇添足或缺失关键环节。
3. **项目文案文字观感**：按钮文案、提示语、空状态、错误提示是否清晰、准确、不歧义、不啰嗦；有无错别字、语病、中英混排不当。
4. **按钮与 UI 设计评价**：按钮位置 / 可见性 / 禁用态是否合理；布局密度；配色对比度（暗色模式可读否）；响应式；滚动 / 溢出；下拉 / 弹窗交互是否遮挡或裁切。

## 第二部分：总体视角（约 4000–5000 字）
跳出单一用户，审视项目整体：
1. **对项目的整体看法**：定位是否清晰、核心闭环是否成立、是否「确定可用」（而非「功能能跑」）。
2. **架构与代码质量**：模块边界是否清晰、有无重复代码、技术债、可维护性、类型安全。
3. **质量与风险判断**：断链（前端调了不存在的接口）、空按钮（onClick 为空或恒 disabled）、未处理异常、性能瓶颈（O(n²) / 大上下文）、数据一致性。

## 发现清单（结构化，附证据）
每条按以下格式，禁止空谈：
- **[编号] 严重度**（P0 阻断 / P1 重要 / P2 轻微）
- **文件:行号**（精确锚点，便于代码执行 Agent 定位）
- **现象描述**（用户可感知的表现）
- **根因推测**（基于代码的逻辑推断）
- **建议修法**（一句话方向，细节留待阶段三方案会议）

## 写作纪律
- 真实、深入即可，内容不受限；但不允许编造未发生的现象或伪造测试输出。
- 每条发现必须能定位到具体代码、测试证据或真实运行记录。
- 禁止「整体不错，建议优化」式空话；必须给出可验证的具体问题。
- 字数不足 1 万视为未完成任务，须补充；宁多勿假。
