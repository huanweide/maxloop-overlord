# 代码执行协议（MaxLoop 魔王系统 · 阶段四）

## 一、派发
Chair 将 `_solutions.md` 中已核准的方案派给代码执行 Agent。执行 Agent 按方案逐条修改代码，并遵守项目适配层的升版与门禁约定。代码执行 Agent 同样受单批最多 5 个约束，需分批派发时本批全部完成后才派下一批，严禁一次性大量并行。

## 二、汇报判定（执行中实时判断）
- **无需汇报**（自行处理，继续推进）：
  - 遇到一般 bug（方案范围内的小错，修掉即可）。
  - 找到稍微绕路但可用的解决方法（不偏离目标、用户无感知差异）。
- **必须汇报**（立即向 Chair 完整汇报，暂停该条执行，等待决策）：
  - (a) 现行方案完全无法解决问题（根因判断错误 / 依赖缺失 / 架构冲突）。
  - (b) 发现重大新问题或大量问题（超出原 IMP 范围，可能影响其他模块或主流程）。

## 三、汇报格式
```
汇报类型: 必须汇报 / (a)方案失效 | (b)重大新问题
IMP-ID: <关联编号，若无则写 NEW-xxx>
现象: <实际发生了什么>
证据: <报错堆栈 / 测试结果 / 代码引用>
影响面: <涉及模块、用户可感知程度>
建议: <重新讨论的方向>
```

## 四、负责人决策流程
1. Chair 收到汇报后，召集相关 Agent 再次开会（回到阶段二 / 三）。
2. 决策：修订方案 / 拆分新 IMP / 暂时搁置（须记入观察池并说明原因）。
3. 形成完整循环，不得绕路、不得顾虑评审、不得节省时间或额度。

## 五、门禁（执行完成后，Chair 亲验）
- 跑质量门禁（见适配层：类型检查 / 测试 / 构建）。
- 亲读 `git diff` 确认改动与方案一致，无遗漏、无越界、无意外文件。
- 不通过则打回执行 Agent 修复，直至全绿；绝不以「Agent 说完成了」替代验证。
- 通过后按适配层做升版（双 changelog / 版本号）+ 提交 + 推送。
