# 复检循环驱动与终止判定（MaxLoop 魔王系统 · 阶段五）

## 一、驱动方式
阶段四代码执行 + 门禁全绿后，不视为结束，而是进入复检：
- 再次分批次派出开会子 Agent（单批最多 5 个，本批次全部返回后才派下一批），撰写新一轮深度体验报告。
- 若子代理通道故障（连续 2 次空返回 / 不落盘），按 SKILL.md「六之二」自动降级为 Chair 主代理亲验，不空等、不卡死。
- 新报告须先复验上轮修复（回归测试 / 复读 diff），再挖掘新坑。
- 回到阶段二评审 → 阶段三方案 → 阶段四执行，形成完整循环。

## 二、轮次管理
- 每轮建 `PROCESS/meetings/round-N/` 目录（N 从 1 递增，不覆盖历史）。
- 阶段一报告落 `round-N/<agent>.md`；整合报告 `_integration.md`；方案 `_solutions.md`。
- 改动随升版进入项目变更日志（见 record-keeping 与适配层）。

## 三、收敛与终止判定
同时满足以下条件，系统判定「项目已无问题」，停止循环并输出总结：
1. 本轮所有开会子 Agent 已全部汇报完毕（无遗漏、无空返回、无超时未交）。分批派发时指所有批次最终齐活，且任一批次未齐不得进入评审。
2. 各报告中提出的问题已全部解决（残留问题数 = 0）。
3. 改进清单已归零（所有 IMP 标记已修复且经门禁 / 脚本验证）。

未满足时继续下一轮；用户未指定上限则至少跑满 5 轮，无限 token 下不主动提前停止。

## 四、防假收敛
- 严禁用「Agent 没发现问题」冒充「没有问题」——须有复验证据（测试绿 / diff 验证 / 真机脚本通过）。
- 观察池中历史未过半问题，每轮复核一次，避免真问题被多数票误杀。
- 门禁（tsc / 测试）全绿是「可停止」的必要非充分条件；体验报告无残留问题才是充分。
